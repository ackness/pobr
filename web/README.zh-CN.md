# PoBR Web

[English](README.md) | **简体中文**

> **⚠️ 测试版。** 应用与底层 wasm/JSON API 仍在迭代中，可能随时变动或不稳定。

PoB2 风格的 PoBR Web 前端。**与计算引擎完全解耦**：只消费 `apps/pobr-wasm`
的 JSON 契约（`web/src/api/types.ts` ↔ `apps/pobr-wasm/src/build_api/`，
形状由 Rust 侧 `apps/pobr-wasm/tests/contract_golden.rs` 钉住），不 import Rust 类型、
不复刻任何公式。

## 多 BD 与阶段

通过“管理 BD”分别保存冰霜射击、旋风等不同玩法。复制当前阶段可规划开荒、过渡和毕业，
每个阶段独立保存加点、装备、技能、配置与笔记。切换时保留当前进度及尚未应用的装备草稿，
原有单份存档会自动迁移。

“分享此 BD · 全部阶段”会下载包含所有阶段与备注的 PoBR JSON 文件。
接收方从文件导入后获得一个独立 BD，不覆盖已有 BD。未应用的编辑草稿只留在本地与完整备份中。
PoB 分享码继续导出当前阶段及其导入的 PoB 配置组。“下载备份”和“备份全部 BD”都包含本机
全部 BD，恢复完整备份需确认替换。存档保存在当前浏览器，可通过文件分享或跨设备迁移；
如果浏览器保存失败，选择器旁会提示及时下载备份。

导入被拒绝时会显示错误，不修改已有 BD、阶段或物品库。当前计算仍有效时，可继续发起
天赋路线及珠宝联合规划，兼容的已完成方案和设置也会保留。导入错误不会清除真正的计算
失败；即使界面仍显示旧数值，计算失败或尚未完成时仍禁止发起新的天赋规划。

缺少稳定技能 ID 的导入宝石插槽仍保留在本机存档、全部阶段分享文件和完整备份中，
包括导入时等级为零的插槽。技能页显示原始名称与“未解析宝石”，不将其纳入阶段计算。
PoB 分享码保留带原始名称的未解析插槽位置，以及编辑后的等级、品质和技能形态。
旧存档仅在能明确匹配原始插槽时补回缺失名称；无法安全恢复名称时，PoB 导出会报错，
不会丢弃插槽或虚构技能身份，PoBR JSON 分享与备份仍可无损保留。

顶栏显示应用版本与实际加载的数据版本。提升页已完成的词条分析与位置选择会在当前阶段内跨页保留；
离页暂停正在运行的分析，全位置分析取消后可继续尚未完成的位置。仅修改预算、区服或赛季不会重新计算。
修改 BD、目标、装备类别、切换阶段或刷新页面会清除临时分析结果。
完整物品文本、替换位置、符文选择、已完成的比较和装备候选也在当前阶段内跨页保留。
离页取消计算与粘贴延迟，返回后不自动重算。计算输入变更使不兼容结果失效；切换阶段重置工作区。

配置页的**快捷入口**说明可选的敌人感电状态与幅度假设，并按当前计算主技能的非零击中伤害，
定位相应的敌人减伤配置。**打开设置**清除目录筛选并聚焦原有控件，不修改 BD。
完整目录、搜索、仅显示已配置与高级导入键值仍保留。该击中伤害清单不代表持续伤害或召唤物的
完整适用性，也不证明所有机制已建模或必有收益；已配置不等于有效。还原恢复导入值，
没有导入值时恢复目录默认值。

配置页默认显示**适用于此构筑**的选项，按当前计算读取的技能、条件与词条筛选；**显示全部选项**列出完整目录。
导入或保存的值始终显示，不适用时另加标记；无法判定是否适用的选项照常显示。各行显示目录自带的说明，
旁边是原始键名。适用不代表该选项已建模。额外的计算上下文只在配置页打开期间请求。

## 快速开始

以下命令均在仓库根目录运行，使用 `web/package.json` 指定的 pnpm 版本；本地 mise 与 CI 均使用 Node 26。
Rust 版本由 `rust-toolchain.toml` 钉定。已有可用工具链时跳过安装步骤。

```bash
# 一次性前置（仓库根目录）：钉定版本的 Rust 与 wasm32 target、wasm-pack、
# Node/pnpm，以及 Web 依赖（`pnpm --dir web install --frozen-lockfile`）
mise run setup
# 不用 mise 时：`rustup target add wasm32-unknown-unknown`，安装 wasm-pack 0.15.0，
# 再运行 `pnpm --dir web install --frozen-lockfile`。

pnpm --dir web build-wasm    # build or reuse verified src/wasm/pkg/ (gitignored)
pnpm --dir web sync-data     # data/<version>/ JSON → public/data/（gitignored）
pnpm --dir web dev           # http://localhost:5173
```

无 wasm / 数据时可用 mock 后端独立开发 UI：

```bash
VITE_POBR_BACKEND=mock pnpm --dir web dev
```

mock fixture 由真实契约生成（契约变更后重跑并提交）：

```bash
cargo test -p pobr-wasm --features diagnostics --test gen_fixtures -- --ignored
```

## 开发与验证

独立引擎下载、Browser/Node.js 接入、agent 技能、Release 附件及 CI 体积比较见
[WASM 打包说明](../docs/wasm-package.md)。

验证范围遵循根目录 [维护者指南](../docs/maintainer-guide.md#验证分层本地提交默认定向验证)。
日常修改运行相关 Vitest 文件与 typecheck；交互变化补对应 Playwright spec。
WASM 产物缺失或其 Rust 源码、依赖、features、工具链变化时重建 WASM；源数据变化或同步数据缺失时
运行 `sync-data`。E2E 使用生产 dist，需要构建当前 Web 代码；`build` 已含 typecheck。

`build-wasm` 在源码、工具链、构建设置和绑定未变时跳过 wasm-pack。
`pnpm --dir web build-wasm --force` 显式重建但保留 Cargo 缓存。
磁盘统计、dev/test profile 与缓存取舍见 [开发工作流](../docs/development-workflow.md)。

Web 经 `src/api/wasmBackend.ts` 在浏览器中调用 WASM，规划器复用计算结果。
`public/_worker.js` 是部署于 Cloudflare Pages 的 HTTP 适配层，Vite 本地复用它处理
WeGame / 市集接口；它不运行 Rust 计算。修改该文件需运行实际 workerd 测试。

## 语言支持

- **界面**：en-US / 繁中 / 简中三语（顶栏切换，UI 文案字典在 `src/lib/i18n.ts`）。
- **游戏名词**：zh-TW 与 zh-CN 边车均已入库（简中来自国服词典转录，
  `node pipeline/gen-zh-cn.mjs` 再生成）；宝石选择器支持简繁英搜索。
- **中文物品输入**：物品词条行与基底名可直接用简中（国服文本），
  wasm 侧模板反查翻译为英文 canonical 后进现有解析器；结构行（`Rarity:`）保持
  PoB 格式；未知中文行与未知英文行一样保留原文、报告 unsupported 诊断，其未建模效果不计入结果。繁中侧只有名词边车
  （词条行模板未入库）。

## 功能

- **新建 build**（PoB2 语义）：启动即有默认角色——Build 页切职业/升华/等级，
  Tree 页点选加点，全程实时重算，无需任何 code。
- **一键导入**：Build 页粘贴 PoB2 code 或 WeGame 分享链接，导入装备、技能和天赋；
  编辑态可导出回可分享的 PoB2 code。
- **装备**：人形槽位布局 + PoB 文本编辑、符文插槽、药剂/护符槽、
  物品库（对比/一键换装）、槽位备注。**打造物品**从游戏基底按合法的词缀阶级与数值构造假设物品；
  **传奇物品目录**可搜索全部暗金及其版本、变体与数值范围。两者都能与已装备物品（含空槽位）对比、
  存入物品库，应用之前不改变构筑。
- **技能**：技能组编辑（宝石/等级/品质/腐化/辅助）、查看技能选择 + 实时伤害占比。可选择效果的形态
  （stat set），Flameblast、分阶段的引导攻击与 Incinerate 可设层数；可停用宝石而不移除；
  可为同伴、幽魂选择怪物及其使用的技能；可把技能组纳入 Full DPS 并设组数与宝石数。
  Full DPS 按所纳入的技能同时使用相加，不模拟循环。
- **天赋树**：加点、属性三选一、珠宝插槽、节点搜索、节点威力热力图。可按**共用**、**武器组 1**、
  **武器组 2** 加点：每次编辑都沿合法路径，先预览加点、转为共用或退点的结果，并显示各组与总的点数预算
  （按全部 24 点剧情奖励规划）。
- **对比**：任选两个已保存的构筑或阶段作为 A 与 B，查看属性差异、物品文本、技能、配置，
  以及画在同一画布上的两棵天赋树；可把单件物品、单个技能组或单个配置值从 B 复制到 A，B 与当前选择不变。
- **计算明细**：技能数值总览、Full DPS 各项贡献，以及每个属性的说明（逐步计算、来源或公式的输入），
  打开时才加载；可在角色与各召唤物之间切换。
- **寻优与市集**：选择位置、目标和预算，自动识别物品类型，展示词条评分、贡献估计与市集权重。直接打开官方市集挑选，不必选择基底或导入商品 JSON。国服使用立即购买模式，点击市集商品的 Sum 可按权重排序。调整预算只更新链接，不重复计算。词条贡献是参考估计，不等于整件换装提升。

**计算明细 → 技能数值总览**也可从侧栏进入。没有主技能的构筑会默认选中综合 DPS 最高的效果（只选一次，
该行带标记）；导入自带的选择保持不变。每个启用组的主动效果分别显示，包括辅助授予效果与零伤害功能技能。
各行显示综合 DPS、平均击中、行动频率、魔力／生命消耗与冷却；无法计算的行显示错误而非零，
未支持词缀与物品问题保留可见，各行不求和。选择一行会同时保存原始技能组与完整主动效果序号，
并使用绑定的武器组进行查看和升级比较。序号包含辅助授予效果，不包含显示别名或数值形态。
删除宝石保留仍存在的查看效果；辅助规划在重排时保持同一效果，不会推荐移除该效果的搭配。
技能选择器按每组保存的完整主动效果序号显示名称。伤害类升级分析要求明确选择有效技能；
仅生命／有效生命目标仍可在未选择技能时计算。打开辅助规划会明确选择该组，
应用宝石方案同时保存评估时使用的效果序号。侧栏与明细仅显示当前构筑版本的计算结果；
总览刷新期间保留键盘焦点，隐藏旧数值与诊断，并暂时禁用选择操作。

辅助规划按当前阶段保留所选技能组的结果、插槽容量、血脉选项与筛选偏好。
离页取消正在运行的分析，返回不自动重算；构筑、目标或设置变化使结果失效。
应用只装备完整重算过的辅助搭配；切换技能组、替换技能配置组、删除组或切换阶段重置工作区，
不提供逐组缓存或刷新后的结果恢复。

辅助结果显示引擎报告的原始基准限制，并把每套被排除的完整搭配与新增限制、原始错误、
无效数值原因对应。诊断排除与手动筛选、推荐分开，不提供应用按钮；推荐显示实际评估的
宝石等级、品质及数值组。收益不会修复基准限制；没有诊断不代表所有辅助机制均已建模。

普通计算会报告实际兼容、所选辅助数据中已确认跳过的条件／缩放数值效果，标明辅助效果与
数值组、stat／数值、实际计算的主技能及形态；触发源限制保留独立来源。例如 Fork 的分叉
投射物惩罚未建模时会披露限制，不会虚构为所有初始命中的伤害修正。零值、未选形态、
不兼容及已有独立处理路径的元数据／控制效果不会被一概排除。此诊断不等于完整覆盖审计。

天赋路径及珠宝联合规划也保留当前阶段内仍兼容的结果和约束；离页卸载画布并停止追踪、
评分、键盘／悬停及热力图工作。输入变更使不兼容结果失效，切换阶段重置归属。
路径诊断保留基准限制，并把被排除的完整加点／撤销方案与新增原因或错误对应。

### 装备组合比较

粘贴完整装备并完成比较后，选择替换位置，点击“加入装备组合”。加入其他候选后，
选择“最多替换件数”（1–10，默认 2），会完整重算保留现状及件数范围内的装备组合。
戒指可以分别加入两个位置比较落位，同一件粘贴物品在每个方案中只使用一次。
候选列表最多保留 16 个位置选项，在当前阶段内跨页保留；离页取消分析，返回不自动重算。

单件收益较低的候选仍会参与双件计算。三件及以上组合在 512 次评估内可穷举时全部
重算，否则按目标筛选，并为可达的各个组合件数保留预算，显示搜索受限提示。
结果按共用目标和约束排序，显示至多五个换装方案及当前装备。切换目标使所有件数上限下的
评估结果失效，需按新目标重算；修改构筑、武器组或候选也会使结果失效。
“应用装备方案”一次性替换所选装备，保留无关装备及另一武器组。候选保留比较时
实际使用的符文和插槽，组合再次检查最终装备的符文数量限制。

计算失败、存在未支持效果、符文限制无法确认或不满足目标约束的方案不能在这里
应用。仅比较已加入的候选与位置，不含市场价格或总购买预算；属性需求及特殊
装备条件仍需玩家核对。药剂和护符继续使用原有比较入口。

### 珠宝与天赋联合规划

在天赋页展开“天赋提升规划”，在“珠宝与天赋联合规划”中粘贴珠宝，添加要比较的
珠宝孔。搜索将保留当前珠宝的路线与各候选位置共同排序，沿用上方目标、过路属性
及最多 8 点预算。通往空孔的路径计入新点数；洗点模式把替换范围珠宝后失去连接的
节点计入退点预算，最终总点数不增加。

每个候选的可分配范围来自当前树版本的计算结果。最多比较 8 个位置，各位置及
当前珠宝分别评估最多 512 条路线，再校验完整最终状态。新增未支持效果、未解析
种子节点及不安全的加点会排除并显示原因。“应用珠宝与天赋方案”一次性写入准确的
珠宝、节点及属性选择，修改角色、目标或预算会使预览失效。

这是有限搜索，不保证全局最优。每个方案更换一个候选珠宝位置，仅支持共用主树；
暂不包含武器组专属天赋、同时更换多个珠宝及装备与天赋一同搜索。

## 数据流

1. 启动：JS fetch `public/data/manifest.json` 列出的全部 JSON → `stageDataFile`
   注入 wasm → `initStagedData()` 构建内存 `GameData` / `BuildData`，后续计算读取内存数据。
2. 导入：PoB2 code 或 WeGame 分享数据 → 结构化 build（角色/树/装备文本/技能组/config）。WeGame 导入需运行 `pnpm --dir web dev` / `pnpm --dir web preview` 或部署随构建提供的 Pages worker，详见 [导入说明与限制](../docs/wegame-import.md)。
3. 计算：编辑态经 `useBuildSession` 组装请求 → `calculateBuildJson(request)` → display_catalog 全量键值 +
   unsupported 词条 + 计算创建的召唤物与各属性的明细种类。普通重算发送 `breakdowns: []`；
   打开某个属性时才为角色或某个召唤物请求它的明细，配置页打开期间另加 `config_context: true`。
4. 归因：`attributionJson(request)` → 逐来源「移除后重算」边际贡献
   （点击触发，计算量 = 1 + 来源数）。
5. 天赋树：静态加载 `public/data/<version>/base/passive_tree.json`；使用旧版本树的构筑加载
   `base/passive_trees/<tree>.json`（不经 wasm）。

## 工作台

应用是基于 Radix 的 shadcn/ui 工作台，每个页面都有直接链接：`/`（概览）、

数据保存在 `pobr-v2-*` 本地存储键中；这个前缀早于现在的命名，为了让已有存档
继续可读而保留（`web/src/lib/sessionStorage.ts` 是唯一拼写它的地方）。仍保存着
第一版界面存档（`pobr-build-state`、`pobr-library`、`pobr-notes`）的浏览器，
首次打开时会复制一次，并保留原始备份；之后不再写入第一版的键。只用过第一版
的浏览器也会沿用当时选择的语言（`pobr-lang`），直到保存显示偏好。存储失败时
应先下载备份。字号或主题切换不会重置编辑草稿。

# PoBR Web

[English](README.md) | **简体中文**

主站为 [pobr.win](https://pobr.win)，备用站为 [pobr-web.pages.dev](https://pobr-web.pages.dev)。
PoBR Web 在浏览器中编辑和计算《流放之路 2》构筑（BD）。应用与 WASM/JSON API 仍为测试版，可能变更。

React 前端通过 JSON 调用 `apps/pobr-wasm`，不重复实现引擎公式。
页面行为见 [Web 契约](../docs/web-contracts.md)，数值与明细定义见[计算输出](../docs/calc-outputs.md)。

## 多 BD 与阶段

打开顶栏“BD 库”，分别保存不同玩法，并复制阶段规划开荒、过渡和毕业。
每个阶段保存装备、加点、技能、配置、笔记及未应用的编辑草稿。切换时会保存当前阶段。
来源 PoB loadout 是导入文件内的一套组合方案；切换它会把来源重新载入当前阶段，覆盖编辑前会提示。

可导入 PoB2 码、受支持的分享链接、WeGame 数据和 `.build` 文件。
构筑码和单阶段存档默认新建 BD；替换当前阶段需明确选择。
分享链接支持 pobb.in、poe.ninja 的 `/pob/` 分享、Pastebin、Rentry、poe2db 和 Maxroll。
poe.ninja 角色页面不是构筑码链接。Planner `.build` 只有方案，不含完整装备。
默认值和缺失输入见[导入格式](../docs/import-formats.md)与 [WeGame 导入](../docs/wegame-import.md)。

JSON 粘贴框只接收已识别的 `.build`／WeGame 来源。PoBR 单阶段存档、全部阶段文件和工作区备份
请用“从文件导入”。导入被拒绝时，当前 BD、阶段和物品库保持原状，错误旁显示恢复建议。
有效的计算及仍兼容的已完成方案可以继续使用；真正的计算失败或待完成状态仍会阻止新的天赋规划。

“分享此 BD · 全部阶段”下载一个 BD 的阶段和笔记，接收方导入后新增独立 BD。
未应用草稿只留在本地存档和完整备份中；取消编辑会丢弃草稿。
PoB 码导出当前阶段及来源 loadout。“下载备份”包含全部本地 BD 和草稿，恢复前会确认替换整个集合。

可在“BD 库”删除 BD 或阶段。确认框显示名称，并提示先下载备份。
至少保留一个 BD，且每个 BD 至少保留一个阶段。删除后打开相邻项，不能撤销删除。
全局撤销／重做最多保留当前阶段的 50 次编辑；导入、切换阶段、BD 或来源 loadout 会清空历史。
天赋编辑另有 30 步历史。两种历史都不会跨刷新保存。

存档只保存在当前浏览器。多个标签页共享 BD、阶段、物品、珠宝和可复用技能组合。
不同项的编辑会合并；同一阶段两边都改过时，写入方保留自己的版本，并报告冲突。
一边删除、另一边编辑时保留编辑。各页尽量保持自己的当前选择。
这只同步浏览器标签页，不是云端备份；跨设备请下载文件。
细节见[工作区契约](../docs/web-contracts.md#web-build-workspace)。

## 功能

| 页面 | 可以做什么 |
|---|---|
| 概览 `/` | 查看关键数值、问题、各技能独立排名和逐来源贡献。 |
| BD 库 `/build` | 管理 BD／阶段、角色、导入、导出和备份。 |
| 技能 `/skills` | 编辑宝石等级、品质、腐化、辅助、形态与武器绑定；选择召唤物及其技能；规划辅助和 Full DPS。 |
| 装备 `/items` | 编辑物品原文、符文、药剂／护符和栏位笔记；比较与装备库中物品；构造假设物品或查找暗金变体与数值。 |
| 天赋 `/tree` | 分配／退还共用或武器组专属点、选属性、编辑珠宝、搜索节点、查看热力图和规划路线。 |
| 配置 `/config` | 管理命名配置组、敌人假设、充能球、自定义词条组和队伍成员。 |
| 提升 `/trade` | 本地评分词条、打开官方市集搜索、比较粘贴物品、规划装备或宝石升级。 |
| 对比 `/compare` | 对比两个已保存 BD／阶段，把单件装备、技能组或配置值从 B 复制到 A。 |
| 计算 `/calcs` | 查看属性明细、技能总览、Full DPS 贡献及逐行词条台账，可查看角色或召唤物。 |

应用直接使用根路径，没有单独的 `/v2` 界面或重定向。浏览器前进／后退可恢复导航。
顶栏的应用版本链接到源码；结果栏底部标明引擎和已加载的数据版本。

### 技能、配置与计算

技能总览独立计算每个启用的主动效果，包括辅助授予效果和零伤害功能技能，各行不求和。
选择一行会保留其技能组、准确效果与武器绑定。没有保存主技能时，应用只在首次选出综合 DPS
最高的效果；导入自带的选择会保留。形态是同一效果的 stat set（数值组），不是额外效果。
Flameblast、分阶段引导攻击与 Incinerate 只提供引擎实际读取的层数输入。
Full DPS 按所选来源同时生效相加，不模拟技能轮转。

停用宝石会保留存档与导出，但不参加计算。腐化状态影响要求腐化的词条，勾选不会改宝石等级。
未解析插槽（包括导入的零级宝石）留在 PoBR 存档与备份中，不参加计算。
PoB 导出需要可靠的来源名称；无法恢复时会报错，不丢弃插槽。
命名技能／配置组、非活动 PoB loadout 和禁用的自定义词条块均可往返保存；只有启用块参与计算。

配置页先显示适用选项。导入值始终可见，无法判定适用性的项也保留。
适用不代表已实现。快捷入口只定位当前命中所用的敌人减伤设置，不改数值。
角色与召唤物的充能球控件分开。“还原”恢复导入时的类型和值，未导入时用目录默认值。
默认值、筛选和原始输入规则见[配置契约](../docs/web-contracts.md#web-configuration)。

属性明细打开时才加载，显示计算步骤、来源查询、公式输入，或明确说明没有明细。
角色与召唤物分开显示，缺失结果不补为零。同阶段重算时可保留淡化的旧数值；失败计算不能作为有效基准。

### 提升规划与限制

先选目标，再比较完整重算结果，最后应用。伤害目标需要有效的查看技能；生命／有效生命目标可不选技能。
推荐会显示当前 BD 的限制及候选被排除的原因。数值提升不证明机制完整支持；
规划器要求安全结果时，新增未支持效果或无效数值会阻止自动应用。

- **市集：** 本地词条评分生成类别、等级、预算和区服筛选。打开官方站点后登录并挑商品。
  国服使用立即购买库存，点击商品的 **Sum** 可按分数排序。当前装备只识别一部分时，
  仍按已识别的加权词条保留最低分，并显示提示；“扩大搜索”移除它。
  词条百分比是估计，不是整件换装收益，不能相加。减益、投射物数量和范围等效果可能不量化。
  应用不自动抓取商品，也不能证明最佳购买方案。
- **粘贴物品：** 在兼容的已装备栏位或已分配珠宝孔比较完整文本。
  预览说明保留、继承或自定义的增幅物；应用只装备评估过的原文。
  市集复制脚本只复制主动点击的商品物品，不含卖家数据。
- **装备组合：** 最多 16 个候选位置，可换 1–10 件，默认 2 件。单件和双件完整评估；
  更大组合在 512 次评估内可穷举时全部计算，否则有限搜索。最多显示五套方案及当前装备。
  同一复制物品不能用两次，最终装备会检查增幅物限制。只比较所给候选，不含市场价格或总购买预算；
  属性需求和特殊装备条件仍需核对。
- **辅助：** 有限搜索完整搭配，并保持查看效果。导入无法确定已解锁容量，需自行设置。
  排除项、词族冲突和保守的一份血脉上限都会生效。普通辅助视为配置调整，主动／血脉宝石另有购买方案。
  新引入的辅助限制会被排除，当前已装备的限制仍会显示。
- **天赋与珠宝：** 路线计入过路点和属性选择，退款保护前置与已插珠宝孔。
  联合规划最多 8 个珠宝位置、8 点预算，各位置及当前珠宝最多评估 512 条路线。
  每套只换一个候选珠宝位置，限共用树；不含武器组专属路线、同时换多颗珠宝或装备与天赋联合搜索。
  未解析种子变换和不安全编辑会保留诊断。

同阶段切页保留仍兼容的辅助、物品与天赋结果。离页取消运行，返回不自动重启。
相关 BD／目标变化使结果失效，切换阶段或刷新重置临时工作。
热力图每批计算 64 个候选，可取消；修改后已完成的部分标为过期。
手动加点预算假设已领取全部 24 点剧情奖励。历史树按导入状态计算与导出，编辑当前树前需明确转换。
对比默认各用自己的配置，也可预览两边都用 A 的配置；从 B 应用到 A 不会修改 B。
搜索、应用、撤销和诊断的准确边界见 [Web 契约](../docs/web-contracts.md)，
时光珠宝与暗金珠宝限制见[珠宝搜索](../docs/jewel-search.md)。参考 BD 引导暂不显示在导航中。

## 工作台

“显示设置”提供**分组详解**、**紧凑表格**和**游戏卡片**，可全局选择，也可逐页覆盖。
重置页面覆盖后沿用全局模式。旧 `itemDisplay` 选择会迁移为全局设置。
装备布局使用同一份分类词条与原文，不为未知词条猜阶级。

还可选择深色（默认）、浅色或跟随系统主题，三种语言，系统／无衬线／衬线字体，
14–32px 字号（默认 16px）及舒适／紧凑间距。密度只改间距，与字号独立。
这些设置不会丢弃草稿、技能选择或规划器状态，也不会触发重算。
窄屏使用导航与结果抽屉，宽屏可固定属性明细栏。不需要外部字体服务。
`⌘K`／`Ctrl K` 打开命令，文本框外按 `?` 查看快捷键；结果栏最多固定 12 个属性。

本地键保留 `pobr-v2-*` 前缀以兼容旧存档。首次打开时，迁移旧 `pobr-build-state`、
`pobr-library`、`pobr-notes`，并在 `pobr-v2-original-backup` 保留原始字符串。
完成标记最后写入，失败后可重试；之后不再写旧键。
只用过旧界面的浏览器沿用 `pobr-lang`，直到保存显示偏好。
无法读取的存档会保留供恢复；工作区保存失败会提供备份下载。

## 语言支持

界面支持英文、简体中文和繁体中文。游戏名词字典随数据版本保存；
简中来自国服字典（`mise exec -- node pipeline/gen-zh-cn.mjs`），宝石选择器可搜索三种语言。
简中物品基底和词条通过模板转为英文再解析，`Rarity:` 等 PoB 结构行保留原格式。
未知文本保留并给出诊断。繁中有名词字典，没有原生词条模板；显示可通过繁简转换回退，
不能视为官方译名。界面翻译不改导入原文或稳定计算 id。

## 快速开始

从仓库根目录运行。使用 mise 的统一环境，精确版本来自 `mise.toml`、`mise.lock`
和 `rust-toolchain.toml`；CI 可用原生安装 Action 读取同一组版本。

```bash
mise run setup
mise run web build-wasm
mise run web sync-data
mise run web dev
```

`setup` 只准备日常环境，不编译产品。oracle、浏览器与树图工具由各自任务按需自动准备。
开发地址为 `http://localhost:5173`。
没有 WASM／数据时可只开发界面：

```bash
VITE_POBR_BACKEND=mock mise run web dev
```

## 开发与验证

遵循[按改动选择验证](../docs/maintainer-guide.md#验证分层)的规则。
按风险和成本选择相关 Vitest、typecheck 或 Playwright；文档只审阅 diff 和链接。
未运行项交给协调者统一验收，不要求每个 worker 都进行本地构建。
WASM 缺失或其 Rust 源码、依赖、features、工具链变化时重建；数据缺失或变化时重新同步。
E2E 使用当前生产 `dist`，`build` 已包含 typecheck。
`build-wasm` 复用已验证且未变化的产物，`--force` 强制重建但不清 Cargo 缓存。

| 命令 | 用途 |
|---|---|
| `mise run web dev` / `mise run web preview` | 开发服务／预览已构建 dist，都提供 HTTP 适配。 |
| `mise run web build` / `mise run web typecheck` | 生产构建／只检查类型。 |
| `mise run web test src/lib/skillSelection.test.ts` | 定向单元测试。 |
| `mise run web test:wasm-contract` | 用已准备的真实 WASM／数据检查前端请求转换。 |
| `mise run web test:worker` | 在 workerd 中检查 HTTP Worker。 |
| `mise run web exec playwright test e2e/build-roundtrip.spec.ts` | 使用当前 dist／WASM／数据的定向浏览器回归。 |
| `mise run web build-wasm` / `mise run web sync-data` | 准备 WASM／复制版本数据到 public。 |
| `mise run web package-wasm` / `mise run web smoke-wasm-package` | 打包／验证 `.cache/wasm-release/` 中的独立包。 |
| `mise run web:tree-art` | 按需准备 vendor、ImageMagick 7/zstd 后再生成树图像。 |

七个共用请求 DTO（传输数据结构）由 Rust 经钉定的宿主开发依赖 `ts-rs` 生成到
`src/api/generated/request.ts`。修改后运行
`mise exec -- cargo test -p pobr-wasm --lib export_typescript_contract -- --ignored` 并提交产物。
普通 Rust 库测试与 PR CI 检查是否过期。其余类型保留在 `src/api/types.ts`，
由 `apps/pobr-wasm/tests/contract_golden.rs` 检查。
契约变化后用 `mise exec -- cargo test -p pobr-wasm --features diagnostics --test gen_fixtures -- --ignored`
重生成 mock 数据。mock 只供界面开发，不验证引擎行为。

## 结构与数据流

`src/app/` 管理路由、设置和外壳；`src/components/` 保存功能面板与共用 shadcn／Radix 控件。
`src/hooks/useBuildSession.ts` 管理编辑、导入和计算。`src/api/` 保存 JSON 类型、生成请求与
WASM／mock 后端，`src/lib/` 放工具，`src/fixtures/` 放 mock 数据，`src/styles/` 放共用样式。
新界面使用共用控件与应用对话框。

后端默认在专用 module Worker 中运行，只有一个引擎，按顺序处理调用。
启动失败时回退页面线程；`?engine=main` 或构建时 `VITE_POBR_WORKER=0` 可强制回退。
启动按数据清单逐文件下载，用浏览器校验 SHA-256，再暂存字节并释放不再使用的副本。
没有原生摘要能力或摘要清单时改由 WASM 计算哈希。
`/data/h/*` 和 `/assets/*` 的路径包含内容摘要，可长期缓存；缺失文件返回 404，页面路由仍返回应用外壳。
后续计算使用初始化时固定的数据快照。

普通编辑请求 `breakdowns: []`，打开属性才请求一项明细；配置页打开时才请求 `config_context`。
逐来源贡献按需移除来源并重算，成本为一次基准加每个来源一次计算。
天赋显示直接读取当前或历史树 JSON。Pages Worker 只适配受限的导入／市集 HTTP 请求，不运行 Rust 计算。
详见[运行时说明](../docs/build-model.md#web-运行时与天赋树规划)、
[开发工作流](../docs/development-workflow.md)与[独立 WASM 包](../docs/wasm-package.md)。

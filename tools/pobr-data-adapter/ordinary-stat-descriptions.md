# Ordinary stat descriptions from RePoE

`--ordinary-domain stat-descriptions` writes `overlay/stat_descriptions.json`
for the existing `StatDescriptionsDef`, GameData loader and equipment affix-tier
lookup. It consumes a pinned RePoE description package and a separately pinned
legacy catalog. No Lua execution, new calculation path or DTO change is involved.

The global `stat_descriptions` scope's unscaled singleton lines come from the
existing strict CSD renderer at representative value **1**. Display markup is
removed with the existing core helper. Successful replacements are removed from
the scope's `unrendered` list. New eligible source IDs are included. This catalog
is representative matching text, not a general stat-value renderer: the existing
tier lookup treats numeric 1 as a capture position. Numeric/display handlers,
negative-only branches and compounds therefore require separate policies before
they can replace legacy templates.

All compounds (including member order and unknown fields), other scopes,
unsupported entries and legacy-only IDs retain their original JSON values.
Global IDs belonging to a legacy compound are preserved as a whole. The receipt
lists each target replacement with CSD branch evidence and each compatibility ID
with its reason and complete source-record hash. A policy pins the canonical JSON
hash of that compatibility map. Changes to an unsupported record or loss of a
previously supported record reject until the compatibility decision is explicitly
updated. `no_description` never means effectless. Original metadata is nested in
the new header; the original catalog is archived verbatim.

The policy pins the RePoE payload, its manifest, patch and legacy input before
parsing. The ordinary fact reader verifies the selected Stats payload and source
lock without reading unrelated tables. Stats membership is not used to invent
descriptions or filter the wider CSD inventory. The description manifest is
archived with the candidate, and source approval remains separate.

```sh
mise exec -- cargo run --locked -p pobr-data-adapter -- \
  --ordinary-facts /absolute/F --facts-manifest-sha256 "$FACTS_SHA" \
  --version 0.5.5.5 --ordinary-domain stat-descriptions \
  --codec-source data/0.5.5.4.2/overlay/stat_descriptions.json \
  --codec-source-sha256 "$LEGACY_SHA" \
  --codec-policy pipeline/stat-descriptions/0.5.5.5-policy.json \
  --codec-policy-sha256 "$POLICY_SHA" \
  --item-descriptions /absolute/native-descriptions/descriptions.json \
  --out /absolute/existing-parent/fresh-descriptions
```

Use actual SHA256 values; [ordinary input/output guards](ordinary-facts.md) apply.
The output contains a domain marker, overlay, original compatibility catalog,
policy, description manifest, fact manifest/lock and producer receipt. Assembly
into a complete ordinary package is explicit; CURRENT and frozen evidence remain
unchanged. Generated modifier rules are not regenerated by this command.
English text here is a matching key, not new translated UI copy. Existing display
translation remains owned by the translation repository.

Focused regressions:

```sh
mise exec -- cargo test --locked -p pobr-data-adapter --bin pobr-data-adapter ordinary_facts::stat_descriptions::
```

## 已实现的使用路径

导入当前 BD → 打开「流派参考」→ 确认主技能与武器组 → 查看近似样本及匹配原因 → 对照宝石、装备、关键天赋 → 在玩家当前配置上试算 → 明确应用。

输入使用 `BuildSession.currentRequest()` 及当前计算结果，包括导入后修改；不只读取最初的 `session.build`。当前仓库没有独立玩家数据库连接，这里的玩家数据是浏览器持久化的 Build 会话。没有新增数据库、上传玩家配置或抓取其他玩家账号的流程。

- 主技能、升华、辅助组合、传奇装备参与本地匹配；普通稀有装备的随机名称不参与。
- 元素抗性缺口来自当前计算值，目标沿用提升页设置。计算中不展示旧结果的缺口。
- 技能与天赋卡片进入现有组合优化器、连通路径规划器。当前页面列出待验证方向，不把差异认定为收益。
- 参考装备可直接「以我的角色试算」，复用完整物品比较、兼容部位检查、增幅器规则与明确应用流程。试算不修改角色。
- 宝石表同时列出当前与参考的已存等级、品质、缺失宝石；整套技能组可展开。装备名称经现有本地化层处理，完整文本保留原文。
- 核心与重要天赋展示名称及效果；历史节点 ID 以当前安装的数据解释，醒目标注版本风险。天赋不参与相似分，也不自动复制节点或推荐洗点。
- 参考笔记只按纯文字渲染，移除 PoB 颜色控制码与结构化注释区，不执行 HTML 或作者指令。
- 粘贴另一份 PoB2 参考码只解码，不覆盖、保存或计算为当前 BD；手动参考只在本页存活，来源与日期标记为未确认。

## 数据来源和边界

`web/scripts/sync-build-references.mjs` 随 `pnpm --dir web sync-data` 运行，从已入库的 `examples/demo-bd-test/builds/` 生成浏览器静态参考集。使用现有 WASM 解码器解析完整 Code，不另写 XML 解码规则。

目前纳入 17 份带 poe.ninja 来源 URL 和抓取日期的样本，均为 Runes of Aldur / 0.5.0 / 2026-06-07。旧版缺少日期或链接的样本不纳入。生成文件位于忽略的 `web/public/build-references/`，不复制到 Git。历史 fixture 中非标准 JSON 的 Infinity/NaN 数值仅在读取元信息时转为 null，字符串不改写；历史 DPS/EHP 不用于收益比较。

2026-09-12 实际核对了 [poe.ninja 构筑入口](https://poe.ninja/poe2/builds/) 和 [升华 + 主技能筛选](https://poe.ninja/poe2/builds/forbiddenrites?class=Gemling+Legionnaire&skills=Oil+Grenade)。站点使用 `/poe2/builds/<league>?class=<canonical name>&skills=<canonical name>`。页面提供常用赛季选项、其他赛季代号及来源入口；默认 Forbidden Rites 是本次核对值，不保证未来仍为最新赛季。链接使用英文目录名称和 URLSearchParams 编码。

这版的「近似搜索」是本地历史样本排序，加 poe.ninja 条件搜索入口；没有实时天梯同步、全服流派覆盖、当前赛季占有率、价格库或预算最优证明。页面直接标明这一范围，不能称作实时推荐引擎。

## 相似度契约

固定匹配分：相同主技能 55 分；相同升华 20 分，否则相同基础职业 10 分；相同主技能组的辅助集合 Jaccard 重合度 × 15；传奇名称集合 Jaccard 重合度 × 10。

升华与基础职业不重复累计。空集合、未知技能与未选主技能不给匹配分；停用组不参与。计算响应中的主技能必须仍在当前组中，避免切换后的旧响应污染匹配。重复元素不增加分数。分数只表示这些可观测信号的重合度，不是强度、胜率、流派使用率或提升百分比。不同主技能的辅助不视作直接可迁移配置。

## 后续产品打磨顺序

1. **同赛季样本覆盖**：先确认 poe.ninja 可用的数据接口、更新边界与访问限制，再加入带时间戳和版本的服务端缓存。以升华 + 主技能分层采样，避免只采顶榜；在覆盖不足时显示样本不足，而非制造推荐。保留历史参考与来源跳转作为可用路径。
2. **流派内部阶段**：为样本加入机制标签、核心传奇组合、等级区间与转型条件。只在同机制与同版本数据内比较分位数；跨机制候选清楚标成转型方案，要求审查配套装备、资源循环和天赋变化。
3. **可执行升级清单**：对玩家明确选择的参考，先生成单项或必要的配套改动，再交给现有引擎计算 DPS、生存、资源与约束。每项显示原因、前置条件、可计算覆盖、收益口径与应用入口。实际市集价格仍须来自当前可验证的商品。
4. **技能与装备细节**：复用游戏目录的图标、标签、辅助适用性与等级需求；在同技能对照中高亮等级/品质差异。装备展示「部位 → 名称/基底 → 核心词条 → 插槽效果 → 原文」，避免按稀有度推断价值。
5. **天赋与文字**：先建立明确的树版本对应关系，才能高亮共同/缺失关键天赋并计算连通路径。说明遵循「观察到什么 → 为什么值得验证 → 有什么依赖 → 去哪里试算」，作者笔记与已验证建议分开显示。
